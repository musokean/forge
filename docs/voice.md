# 语音交互（#11：Phase 1 整句级 → **Phase 2 流式 + Phase 3 打断**）

```
麦克风 ──▶ VAD 分段 ──▶ STT 转写 ──▶ Agent ──▶ TTS 合成 ──▶ 播放
   ▲                    (边说边出草稿)   │        (一句一合成)
   └────────── 播放/生成期间仍在听 ───────┴──▶ 检测到插话 → 立刻停播 + 取消生成
```

**Phase 1（既有）**：说一句 → 静音自动结束 → 整段转写 → 答完 → 整段合成 → 播放。
一句一答能跑，但**首句出声延迟 = 整段答案生成 + 整段合成**，且它说话时你插话没用。

**Phase 2 流式**：
- **转写流式**：说话期间每隔 `partial_ms`（默认 1s）把已采集的音频重转一次，先出草稿
  （真机实测：`你好,请用` 在整句说完前就出来了）。
- **应答流式**：Agent 的增量文本进 `SentenceSplitter` 切句，**合成一句就播一句**，
  首句出声不再等整段答案（真机实测：一次回答切出 3 句、按序播放）。

**Phase 3 打断（barge-in）**：forge 说话/生成期间麦克风**仍在听**：
1. 检测到持续说话 ≥ `barge_ms`（默认 300ms）→ **立刻停播**（`StreamingSpeaker.stop()` 打断当前播放并丢弃未播队列）；
2. **取消当前生成**（`Agent.run(interrupt_check=...)`，复用既有中断语义：返回已生成部分）；
3. **保住已经说的那半句**（`MicListener.take_utterance()`）→ 直接作为下一轮输入，**不用再说一遍**。

## 为什么能「不用麦克风、不出声、不调模型」就测

链路里三块都做成了可注入，机制与硬件解耦：

| 组件 | 真实现 | 测试替身 |
|---|---|---|
| `AudioSource` | `SoundDeviceSource`（真麦克风） | `FileSource`（音频文件当麦克风，遍与遍之间插静音供 VAD 切句）· `ScriptedSource`（合成「有声/静音」块，纯逻辑） |
| `AudioSink` | `FFplaySink`（ffplay 子进程，`stop()`＝terminate，打断的即时性来源） | `NullSink`（记录「本该播什么、什么时候被打断」） |
| VAD / 切句 | `EnergyVAD` · `SentenceSplitter` | 本身就是**纯状态机**，喂块即可断言边界 |

于是「分段边界 / 打断时序 / 流式顺序 / 首句延迟」全部能确定性复现，进 CI。
真机验收只剩最后一步（真人戴耳机说话），见下。

## 跑起来

```bash
pip install "handcraft-agent[voice]"          # sounddevice / numpy / edge-tts / openai-whisper

forge --voice                                  # Phase 2/3（默认）：真麦克风 + 真播放
forge --voice --voice-phase1                    # 退回 Phase 1 整句级
forge --voice --stt-model small                 # 中文识别要求高时换更大的 whisper 模型
forge --voice --barge-ms 500                    # 插话判定阈值（越小声的环境调大越稳）

# 不用麦克风也能跑完整链路（自测/回归、CI 友好）
forge --voice --audio-source file:问句.wav --voice-sink null --voice-rounds 1
forge --voice --audio-source file:问句.wav --voice-loop --voice-rounds 5   # 同一句连跑 5 轮
```

| 参数 | 作用 |
|---|---|
| `--audio-source mic\|file:PATH` | 音频来源；`file:` = 文件当麦克风（无需硬件） |
| `--voice-rounds N` | 最多几轮就退出（0=一直跑） |
| `--voice-loop` | 文件源循环播放（多轮回归用；默认不循环，避免把同一句当成插话） |
| `--voice-sink speaker\|null` | 播放方式；`null` = 只走流程不出声（自测用） |
| `--barge-ms N` | 连续说话多久算插话 |
| `--stt-model NAME` | whisper 模型（base/small/medium…） |
| `--voice-phase1` | 用 Phase 1 整句级链路 |
| `--half-duplex` | **外放不用耳机**：它说话时闭麦，防自激（代价：播放时不能插话） |
| `--ptt` | **按住空格说话**：不按不采集、按下即打断、松开提交（完全不用耳机也能随时插话） |

## 不用耳机怎么用（外放自激问题）

**戴耳机是默认姿势**：外放时喇叭里的 TTS 会被自己的麦克风听回去 → 被当成「用户说话」→ 它开始回答自己的话 → 死循环。三条路：

| 模式 | 命令 | 能免耳机 | 播放时能插话吗 | 生成时能插话吗 |
|---|---|---|---|---|
| 全双工（默认） | `forge --voice` | ❌ 会自激 | ✅ | ✅ |
| **半双工** | `forge --voice --half-duplex` | ✅ | ❌（要等它说完） | ✅ |
| **按住说话** | `forge --voice --ptt` | ✅ | ✅（按下即停） | ✅ |

- **半双工**：它开始出声时闭麦（`listener.set_muted(True)`），播完等 `guard_ms`（默认 300ms）让喇叭余音散掉再开麦。它**思考期间**仍可插话——那时喇叭还没出声，不存在回声。
- **按住说话（PTT）**：不按不采集（**外放时它说什么都听不到**，实测文件源里灌着语音、不按键 8 秒零轮次），按住空格 = 立刻停播 + 开麦，松开 = 提交这一句。句子边界是「松手」，不依赖 VAD 分段。Windows 用 `GetAsyncKeyState` 轮询（`msvcrt` 只能拿按下事件、判断不了长按）。
- **回声消除（AEC）已实现**（`--aec`）：真免手 —— 既不闭麦也不按键，它说话时你插话照样听得见。见下节。

## 回声消除（AEC）：既不闭麦也不按键

半双工与 PTT 都能免耳机，但都**牺牲了「它说话时随时插话」**。AEC 用**正在播的音频当参考信号**，
自适应估计回声路径（喇叭 → 空气 → 麦克风），从麦克风里减掉回声 —— 于是它说话时麦克风里只剩你。

> **不用每次手打开关**：在 `config/models.yaml` 里写一次 `voice: {aec: nlms}`，之后裸跑
> `forge --voice` 就是外放免耳机（命令行开关仍然最优先；`--aec none` 可临时关掉，
> `--stt-model small` 之类同理）。

```bash
forge --voice --aec            # 默认 nlms 引擎；也可 --aec pyaec（装了才可用）
forge --voice --aec --aec-lead-ms 150   # 参考信号提前量按房间/设备微调
```

| 项 | 说明 |
|---|---|
| 引擎 | **`nlms`（纯 numpy 分块 NLMS 自适应 FIR，默认）**；`pyaec`（C 扩展，本机 3.13 无 wheel 装不上，留作可选）· `none` 关闭 |
| 播放 | AEC 模式改用**进程内播放**（`sounddevice`）：`ffplay` 是外部进程，拿不到正在播的样本就没法消（`--voice-sink null` 时没有参考，会明确提示「等价直通」） |
| 滤波器长度 | 默认 200ms：覆盖「输出缓冲 + 声学延迟 + 混响」，**不要求精确对齐时间戳**（这是它在真实链路里稳的关键） |
| 参考提前量 | **按设备实测输入延迟自动推算**（`--aec-lead-ms 0` = 自动，默认）：输出侧已在推参考时按流延迟补偿，所以只需「输入延迟 + 余量」；本机实测流延迟 26ms → 提前量 41ms。拍常数会偏（硬编码 120ms 时差 30~90ms），偏得越多滤波器越要拿抽头去凑对齐，ERLE 越低 |
| 参考对齐 | **一次锚定后按样本计数推进**（`ReferenceTap.stream`）：每块都用墙钟会把滤波器学糊（实测 ERLE 从 30dB 掉到 2dB） |
| 双讲 | **初始收敛期不冻结**（否则学不到房间响应），收敛后用「回声能量比」判双讲并冻结自适应 —— 否则用户一说话滤波器就被带偏 |
| 冷启动 | 前 ~300ms 系数还在学房间响应，这段**当静音处理**（真实产品同样有这段保护） |
| 观测 | 收尾时打印 `aec: {engine, frames, frozen, erle_db}`，`erle_db` 低于 ~10dB 说明消得不够（房间/音量/提前量需要调） |

**实测（本机合成回声路径）**：稳态 **ERLE ≈ 30dB**；只有回声时**不触发**任何 VAD/抢话（关掉 AEC 则触发，控制组对照）；
真人插话**照常触发**（近端语音与残差相关 0.98，说明 AEC 只消回声不消人）。

**诚实边界**
- NLMS 是**线性**回声消除：喇叭大音量非线性失真、房间强混响时消不干净（真实房间 ERLE 通常 10-20dB）。
- **同声卡假设**：播放与采集用同一块声卡（同一时钟）时样本计数才准；跨设备长时间跑要周期性重锚（`ReferenceTap.reset_cursor()`）。
- **移动设备要重收敛**：麦克风/音箱位置一变，学到的房间响应就过期了 → 重新开始一段语音即可（冷启动保护会重新学）。
- 需要按房间调 `--aec-lead-ms`；`erle_db` 是最直观的判据。

### 为什么 AEC 在不同机器上表现差别很大

回声消除要把「喇叭正在播的声音」从麦克风信号里减掉，前提是**参考信号与麦克风在时间轴上一一对齐**。
真实设备的延迟 = 输出缓冲 + 输入缓冲 + 声学传播，合计可达数百毫秒：本机实测 **460~520ms**，
而声卡驱动报出来的输入延迟只有 **26ms** —— 任何写死的常数都会偏，偏了滤波器就学不会。

所以 forge 会**在每次播放时自己测一遍**：

- 每个麦克风块读进来时记下**采集时刻**，参考按该时刻取（不是按「读了几次」推算，那个会被偶尔读慢的块带偏）；
- 用**能量包络**做互相关来估延迟（波形在笔记本上因驱动增强/削波而变形，相关只有 0.045；包络几乎不变形，相关 0.3 左右）；
- 单窗取峰在弱回声下会乱跳，因此改成**跨帧累积相关谱**（每帧贡献整条曲线、按活跃度加权累加）+ **强相关才采纳**（峰 ≥0.25、明显高于谱中位、累计 ≥3 帧、突变 ≤300ms），否则沿用上一版可信值。

实测：估计序列 480→486→493ms（抖动 13ms），对齐后播放期间残差低于 VAD 阈值、**不会把自己的话当成用户输入**。

如果你的机器上 AEC 效果不理想，通常是**喇叭→麦克风耦合太差**（麦克风离喇叭太远、音量太低）：
可以调高音量、让麦克风靠近喇叭，或直接用 `--ptt`（按住空格说话）/ `--half-duplex`（播放时闭麦）。

### 怎么打断它（四种模式对照）

| 模式 | 它**正在思考/生成**（喇叭还没响） | 它**正在说话**（喇叭在响） |
|---|---|---|
| `--voice`（默认，假设戴耳机） | 直接开口 ✓ | 直接开口 ✓（外放会自激，所以默认按耳机用） |
| `--half-duplex` | 直接开口 ✓ | ✗ 不行（播放期闭麦防自激）—— 等它说完，或等它下一轮思考时插 |
| `--ptt` | 按住空格说话 ✓ | 按住空格说话 ✓（**按下即打断**） |
| `--aec` | 直接开口 ✓ | 直接开口 ✓（外放免手，靠回声消除） |

**打断之后会发生什么**：

1. 喇叭**立刻停** —— 正在合成中的那一句也不会补播（轮次代号机制，2026-10-03 修）；
2. 正在生成的内容被取消，已生成的部分作为「部分回答」保留；
3. 你**已经说出口的那半句不会被丢掉** —— 它等你把话说完整（静默 0.8 秒）后，把「抢话那一刻的半句」和后面说的**按时间顺序接起来**一起理解（2026-10-03 修掉「只识别前半句」）。

**灵敏度**：`--barge-ms N`，默认 **300ms**（连续说满 0.3 秒才算抢话）。嫌不灵就调小（`150`），容易误触就调大（`600`）。

**退出**：说「退出」/「exit」，或输入 `/exit`；Ctrl+C 直接终止进程。

**插不进去时先查两件**：① 你当前模式是不是 `half-duplex`（播放期本来就闭麦，这是设计不是故障）；② 说话时长够不够 `barge-ms`，以及麦克风电平能不能越过 VAD 阈值（日志里出现 `⏹ 已中断` 才代表抢话被识别）。

## 测试阶梯（哪一级需要什么）

| 级别 | 测什么 | 需要什么 | 结论 |
|---|---|---|---|
| **L1 离线机制** | VAD 分段 · 打断状态机 · 流式顺序与首句延迟 · 句级播放 | 注入式音频源 + 假播放器，无硬件无模型 | ✅ `test_voice.py` **39 例**进 CI（`test_interrupt.py` +2） |
| **L2 无麦闭环** | 真 STT → 真 Agent → 真 TTS 全链路、流式切句 | 音频文件当麦克风，静音 | ✅ 本机实测（真 whisper 草稿 + 真模型流式 + 3 次句级合成） |
| **L3 半真机** | 真采集路径、重采样、驱动缓冲、声学回声 | 扬声器放 + 麦克风收（会出声）；或装 VB-Cable 做数字回环 | ⚠️ 未做：本机「立体声混音」只在 WDM-KS 下暴露，PortAudio 打不开；声学回环会出声 |
| **L4 真机验收** | 打断体感、耳机回声、现场噪声下的阈值 | **人戴耳机说两句** | ✅ **2026-09-29 真机验收通过**（用户实测）：说一句答得对 · 它说话时插话立刻停并接上新话 · 首句出声明显更快 |

本机已验证：真麦克风可开（采到 1.4s，环境底噪 RMS≈0.005）· **15 秒环境噪声不误触发**（阈值默认 0.012）· 真 whisper `base` 中文可用但精度有限（实测「12 乘以 8」→「12×18」，要准确请 `--stt-model small` 或后续接 SenseVoice/FunASR）。

**首句出声延迟实测**（t=0 为转写完成，whisper base + edge-tts + 本机）：三句分别在 1.90s / 2.04s / 2.10s 切出 → **第一声 +4.18s**、第二声 +6.80s；整段生成在 **+7.23s** 结束——也就是说**老链路要到 7.23s 之后才开始出声**（还要再加首句合成时间，合计约 9.5s）。流式把首句出声从约 9.5s 提前到 **4.18s**。

## 已知限制（诚实标注）

- **外放 + 麦克风会自激**：TTS 被麦克风收回去 → 被当成新指令 → 死循环。**必须戴耳机**（这是 Phase 3 的硬性前提）。
- **whisper `base` 中文精度不够**：数字/近音词会错。`STTEngine` 是可插拔的，接大模型或 SenseVoice 是低成本改造。
- **转写流式是「重转写」而非真流式 ASR**：实现上每隔 `partial_ms` 对已采集音频重跑一次 whisper（CPU 上 base 约 1-2s/次）。好处是零新依赖、串口麦克风也能用；代价是草稿延迟约等于一次转写耗时。要更低延迟需换流式 ASR。
- **打断阈值是能量判定**：嘈杂环境下可能误触发（调大 `--barge-ms`），安静环境灵敏度足够。
- **L3 未做**：真声学回环（扬声器放 → 麦克风收，会出声）与数字回环（需装 VB-Cable，本机「立体声混音」在 PortAudio 下打不开）都还没跑。L4 真人验收已通过（见上表）。
- **麦克风设备选择**：目前用系统默认输入设备（`--audio-source mic`），还没有「指定输入设备」的参数——多麦克风的机器需要靠系统默认设备切换。
- **半双工牺牲了「边说边插话」**：这是它的原理决定的（闭麦才不自激）。要既免耳机又能随时插话 → `--ptt`；要完全免手（连键都不用按）→ `--aec`（已实现，但需按房间调 `--aec-lead-ms`）。
- **PTT 只在 Windows 生效**：`KeyHold` 走 `GetAsyncKeyState`；其他平台 `held()` 恒为 False（功能会「听着但没反应」），需要各平台的按住检测实现。
- **闭麦会清空当前缓冲**：半双工/PTT 下，闭麦瞬间「已经说了半句」的音频会被丢弃——所以实现里抢话那半句是**先接住再闭麦**（`carry["pending"]`），这是踩过坑的地方。
