# 人脸识别：让 Agent「认识」人（#18 Phase 2）

Phase 1 只回答「**有没有人、脸在哪**」；这一层回答「**这是谁**」——前提是你先把人**登记**过。

```
camera.capture()  →  Frame + [Face]        # 有没有人
faces.crop_face() →  一张脸的裁剪
embedder.embed()  →  128 维特征向量
store.match()     →  名字 / 「未知」
```

**核心观念：「认识」= 你自己的特征库，不是模型记忆。** 视觉模型每看一帧都只是在描述画面，
不会跨会话记得谁是谁；让它认识人的，是这里登记下来的向量库。所以登记这一步是核心，模型只是可替换的零件。

## 四个工具

| 工具 | 干什么 | 只读分级 |
|---|---|---|
| `face_people()` | 列出已登记的人（名字 + 各几张向量） | ✅ 只读 |
| `face_who(index=0)` | 看一眼并回答「这是谁」，多人时逐个给 | ✅ 只读 |
| `face_enroll(name, samples=3)` | 抓几帧、取向量、登记到该名字下 | ⚠️ 写操作 |
| `face_forget(name)` | 彻底删除该人的全部向量 | ⚠️ 写操作 |

## 怎么用（不用 Agent）

```python
from forge.camera import OpenCvFrameSource, HaarFaceDetector, capture
from forge.faces import crop_face, make_embedder, FaceStore

det, emb, store = HaarFaceDetector(), make_embedder(), FaceStore()
with OpenCvFrameSource(0) as src:
    frame, faces = capture(src, det)

# 登记
vecs = [emb.embed(crop_face(frame.image, faces[0])) for _ in range(3)]
store.enroll("老王", vecs)

# 识别
m = store.match(emb.embed(crop_face(frame.image, faces[0])))
print(m.name or "未知", m.score, m.reason)
```

## 判定规则：两条闸门，宁可不认

| 参数 | 默认 | 含义 |
|---|---|---|
| `threshold` | **0.36** | 余弦相似度低于它就回「未知」（SFace 官方参考值 0.363） |
| `margin` | **0.03** | 最佳与次佳至少差这么多，否则也回「未知」 |

第二条是防「认错人」的关键：两个人长得像时，最佳分可能刚过阈值但优势不明显 ——
这时候说「未知」比认错人便宜得多。**代码从不硬猜** ✓。

> **阈值与维度强相关**（实现时踩到的真坑 ✗✓）：随机单位向量的 |cos| 期望约 `1/√d`。
> 8 维时 ≈ 0.35（正好贴着 0.36 阈值，导致不相干的人也过闸 ✗）；128 维 ≈ 0.09（安全 ✓）。
> 所以换提取器（维度变了）**必须重新校准阈值，并重新登记**（维度不一致会明确报错）。

## 隐私（硬约束，请当设计前提读）

1. **只存特征向量，绝不存原图** —— 库里 `faces` 表只有 `vec` 一个 BLOB 字段；删一个人就是删几行向量，
   **无法从库里还原出人脸** ✓；
2. **`data/` 与 `*.db` 已在 `.gitignore`** ✓ —— 结构上进不了 git、上不了 GitHub；
3. **`face_forget(name)` 彻底删除**（含全部向量，不可恢复）；
4. **登记需本人同意** —— 代码只能提供删除能力，「同意」这件事由使用者负责。

## 尚未验证的部分（如实标注）

- **真人识别精度未测** ✗：本机没有摄像头，也没放模型 → 自动化测试只覆盖**判定链路**
  （相似度、登记/删除/持久化、阈值与 margin 两条闸门、维度不一致、能力探测、工具分级）。
- **对齐问题**：SFace 官方建议先做人脸对齐（`alignCrop`，需要关键点）。现在用 Haar 框直接裁再缩放，
  **不做对齐**，精度会低一些。想更准就把检测器换成能出关键点的（如 YuNet），
  再走 `cv2.FaceRecognizerSF.alignCrop` —— `FaceDetector` 接口已经留好位置。
- 登记质量比算法更重要：**正脸、光线足、别太远**，每人 3~5 张不同角度最稳。

## 多人 + 「谁在说话」（Phase 3）

一个人好办，一屋子人就要回答两个新问题：**现在几个人、谁在跟我说话**。

### 为什么不用「音源定位」或「唇形识别」

- **单麦克风没有方向信息** ✗ —— 定位不了谁在出声；
- **Haar 检测器不给关键点** ✗ —— 做不了唇形/张嘴幅度。

所以这里用**两个确实拿得到**的信号叠加 ✓：

| 信号 | 怎么来 | 说明 |
|---|---|---|
| **嘴部区域帧间运动** | 取脸框下三分之一，缩到 32x16 后逐帧比 | 嘴明显动 → 分数高。极小图 + 均值差：极便宜（与摄像头分辨率无关）|
| **脸区大小** | 检测框面积（`camera` 已按面积降序） | 镜头前通常是离得近的那位在说；也用作平局次序 |

判定同样**不硬猜** ✓：最高分必须过 `min_motion`，**且**至少是第二名的 `ratio` 倍，
否则明确回「不确定」：

```
（观察 3.0s）在场 2 人：老王、未登记#2。正在说话：老王（嘴部运动 0.0843）。
（观察 3.0s）在场 2 人：老王、未登记#2。谁在说话：不确定 —— 老王 与另一个人的嘴动分太接近（0.0431 vs 0.0402），分不清谁在说。
```

### 一个人只该有一个名字

`Tracker` 按**质心距离**把每帧的检测框关联成稳定的 `track_id`（带 TTL 与迟滞）：
同一个人小幅移动**不会换 id** ✓；离场超过 `ttl` 秒才回收；跳得太远（超过 `max_dist × 脸宽`）
才开新 track —— 这样**侧脸/遮挡一两帧也不会让人名乱跳** ✓。

识别**按 track 缓存**并**降频**（每 `recognize_every` 帧一次）：既省算力，又能在某一帧没认出来时
**保留上次的名字**（不让名字一闪一闪 ✓）。

### Agent 怎么用

| 工具 | 干什么 | 只读分级 |
|---|---|---|
| `who_is_speaking(seconds=3, index=0)` | 盯几秒，回「在场几个人、都是谁、谁在说话」 | ✅ 只读 |

没登记过人也能用 ✓（名字显示为「未登记#N」）；没装人脸模型也能用 ✓（只是没有名字）。

### ⚠️ 已知边界：纯视觉**分不开「说话」与「安静」**（实测）

2026-10-03 真机对照（同一人、同一机、同一套参数、各录 15 秒，只看最大的那张脸）：

| | 嘴动分 中位 | 嘴动分 max | 超过 0.015 的秒数 |
|---|---|---|---|
| **说话时** | 0.0199 | 0.0224 | ~15/15 |
| **安静时** | **0.0159** | **0.0223** | **9/15** ✗ |

**两个分布重叠** ✗ → **不存在能分开它们的门限**（抬到 0.025 会把说话时的 0.0199 也一起漏掉 ✗）。
根因：200px 宽的脸上取 32x16 嘴部区，每格约 6x4 像素，**检测框每帧抖动 1~3 像素（整块平移）就已经盖过嘴动的贡献** ✓。

**因此（已修复 ✓）**：
- `min_motion` 默认 **0.03**（高于实测两个分布的 max ≈0.022 ✓）→ **纯视觉**模式下只声称「**明显动嘴**」✓，
  **不声称「在说话」** ✗（措辞会明确写「未接音频，不能确认在说话」✓）；
- **音频 VAD 门控**（`voice.LiveSpeechGate`）✓✓ —— 把「谁在说话」拆成两个模态各出自己可靠的那一半：

  | 问题 | 由谁回答 | 为什么可靠 |
  |---|---|---|
  | **此刻有没有人在说话** | **音频**（能量 VAD）✓ | 安静时给 0、有人说话给 1 ✓（实测门控阈值复用 `EnergyVAD` 的 0.012 ✓）|
  | **是谁** | **视觉**（嘴动分）✓ | 在「确实有人在说话」的前提下，挑动嘴最明显的那个给名字 ✓ |

  于是：音频说「没人说话」→ 直接回**没人说话** ✓（视觉噪声再高也不作数 ✓✓）；
  音频说「有人在说」→ 视觉给出名字 ✓；拿不到麦克风 → 如实退回纯视觉并**改措辞** ✓（不假装 ✓）。

  **音频模式下，视觉不得否决** ✗✓（2026-10-03 真机踩到并已修）：真机上曾出现「音频报了 2 秒
  有人在说话，但工具仍回没人说话」✗ —— 因为嘴动分 0.0281 低于纯视觉阈值 0.03，**把音频的判定
  一票否决了** ✓。门控装反了：**「有没有」由音频定，「是谁」才归视觉** ✓✓。修好后的优先级：

  | 音频 | 画面 | 结论 |
  |---|---|---|
  | 有人在说 ✓ | **只有一个人** | **归给他** ✓（音频定有没有，人数定是谁 —— 都不依赖不可靠的视觉打分 ✓）|
  | 有人在说 ✓ | 多人，某人嘴动明显领先 | 报他 ✓ |
  | 有人在说 ✓ | 多人，嘴动分不出 | **「不硬指」** ✓（明说不知道是谁 ✗）|
  | 没人说话 ✗ | 任何 | **没人说话** ✓（视觉噪声不作数）|

  **已知边界**：若**说话的人在画面之外**（只有别人在框里），「只有一个人 → 归给他」会**误归属** ✗
  —— 这是本设计为换取"不被噪声否决"而接受的代价 ✓，已在 `reason` 里写明依据（音频判定 + 人数 + 嘴动分）✓，
  便于使用者自行判断 ✓。

- `min_motion`（默认 0.03）：低于它算「没人明显动嘴」。光线暗、脸小、离得远时**调小**；
  想说"必须动得很明显才算"就**调大**。
- `ratio`（默认 1.5）：最高分要领先第二名这么多倍才算数。
- `ttl`（默认 1.5s）：多久没跟上算离场。
- `recognize_every`（默认 10 帧）：识别降频档位 —— 人多机器慢就调大。

### 仍属未验证的部分（如实标注）

- **真人多人场景已实测** ✓（2026-10-07 凌晨，两位真人轮流说话 ✓）：判定逐条落盘 ——
  「翠花 · r=0.65 · 延迟0.30s（269 帧）」「满仓 · r=0.81 · 延迟0.23s（347 帧）」，并如实回
  「样本不足」「没有画面里的人」「没人跟声音明显同步（0.16<0.35）」✓✓。**最佳延迟实测 0.23~0.30s**
  （= 嘴唇领先声音 ✓，故必须搜延迟 ✓）。自动化测试覆盖的是**判定链路**（跟踪稳定性、TTL 回收、
  降频计数、名字缓存不闪、两条闸门、拿不准就说不确定），用的是合成图；
- 已知会退化的场合：**侧脸/低头**（Haar 检测不到 → track 会 misses 上升）、**遮挡**、
  **光线太暗**、**说话人幅度小**（嘴动分接近噪声）。
- 想让"谁在说话"更稳的上限做法：换能出关键点的检测器（YuNet）+ 音频 VAD 做融合 ✓ ——
  `FaceDetector` 接口已经留好位置。

## 检测器：YuNet 优先，Haar 兜底

| 检测器 | 模型 | 实测（本机，逆光）| 关键点 |
|---|---|---|---|
| **YuNet**（默认，有模型时）| 227KB ONNX | **12/12 命中**，分数 0.93~0.94 ✓ | ✅ 5 个 |
| Haar（兜底）| 随 opencv 发布 | 1/12 ✗（逆光下几乎没有）| ❌ |

`make_detector()` 按能力挑：**YuNet 能用就用 YuNet** ✓，否则 Haar ✓。想强制指定就设
`face.detector: yunet|haar|auto`（`yunet` 不可用时会**明确报错**，不静默降级 ✗）。

**阈值必须给足**：YuNet 默认 `score_threshold=0.9`。我们踩过 ✗✓：随手写 0.5 时，一张**画面里其实
没有脸**（人背对镜头）的帧把**肩膀**框住并打了 0.50 分 —— 典型假阳性 ✓。0.9 下同一批画面 12/12 命中 ✓。

### 对齐（alignCrop）值不值？—— 实测数字，不是宣传

同批 10 帧、同一人，三条路对照（都是 YuNet 检测）：

| 路径 | 命中 | 中位相似度 |
|---|---|---|
| `alignCrop` 对齐 | 10/10 | 0.892 |
| 裁剪（默认 25% 边距）| 10/10 | **0.894** |
| 零边距裁剪 | 10/10 | 0.862 |

- 对齐比「紧贴框裁剪」好 **+0.030** ✓ —— 方向符合预期 ✓；
- 但**同一个 +0.03 靠"裁剪时外扩 25% 边距"也能拿到** ✗ → **对齐并不比默认路径更好**；
- 三条路**全部 10/10**、都远高于阈值 0.36 → **功能上无差别** ✓。

**所以 YuNet 的价值在「检测更稳」，不在「识别更准」** ✓。`embed_aligned()` 留着（关键点还能作他用、
以后换更强的识别模型时对齐才有意义），但别把它当精度银弹 ✗。

## 让对话知道在跟谁说话（`--identify`）

多人的**存储**天然支持（`people` / `faces` 两张表 ✓），但「认出是谁」和「跟人对话」原本**没接上**：
语音轮里根本没有开摄像头。`--identify` 把它接上：

```bash
python main.py --voice --identify            # 语音轮里带现场身份（默认关 ✓）
```

- 后台约 **1Hz** 看一眼画面（每次现开现关摄像头 ✓），结果经 `Agent.set_ambient()` 注入 **system 首条**
  （与对话历史分开 ✓，技能切换/新开对话都不会丢 ✓），于是它可以**按名字称呼**、也知道来了新面孔 ✓。
- **单人**在画面里 → 回答前会说明「刚才说话的是他」✓（可靠的两个信号：音频定有没有 ✓、人数定是谁 ✓）。
- **多人**在画面里 → 如实说「嘴动分分不出是谁」✗✓ —— 这是实测结论（嘴部运动分**分不开**说话与安静，
  见上文「已知边界」✓），所以**不硬指** ✓。

**隐私**：默认关闭 ✓；开启后也只读**特征与相似度**、**不保存任何图像** ✓；`face_forget` 可整个删除 ✓；
摄像头侧出错只会退化成「没有名字」✓，不影响语音 ✓。

**已知边界（2026-10-06 实测更新 ✓）**：两人同时在库的误认率**已实测** ✓ —— 两人各自登记（17 张 / 12 张，

另一人的连续姿态）给出「异人最高 **0.307**」✓。**产品路径 `face_people` / `face_who` 均当场认对** ✓。
**三人库已实测** ✓（2026-10-07，登记「富贵」后当场量 ✓）：同人最低 **0.482**（满仓；翠花 0.857 / 富贵 0.837）、
